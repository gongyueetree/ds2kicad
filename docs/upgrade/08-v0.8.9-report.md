# v0.8.9 — 图区截取修复：几何收归确定性引擎

## 1. 现象

图集四张卡片全部显示为"大片空白 + 一两行文字"，`＋留白` 无效，空白告警一次未触发。

## 2. 根因定位

### 2.1 页码是对的，坐标是错的

逐张读取截图内容：

| 卡片 | 声明页码 | 实际裁到的内容 |
|---|---|---|
| 应用参考电路 | p.1 | `…证译文的准确性` / `English Data Sheet: SLVSJZ9` → 首页译文免责声明（页面最底部） |
| 管脚排布图 | p.3 | `提交文档反馈` + 页码 `3` → 第 3 页页脚 |
| 内部功能框图 | p.23 | `提交文档反馈` + 页码 `23` → 第 23 页页脚 |
| 封装图 | p.32 | 页脚分隔线 |

裁出的页脚数字与声明页码一一对应 ⇒ PDF 取回、`selectRelevantPages`、`remapDerivedPages` 全部正常。**问题被隔离在 bbox 的 y 坐标上**，且错误方向一致：页面中上部的图被裁到了页面底部，符合 y 原点反转（BOTTOM-LEFT 被当作 TOP-LEFT）的特征。

### 2.2 坐标来自 Gemini

`lib/heuristics.js` 的 `findFigures()` 返回语句为：

```js
return [...blocks, ...pincfg, ...apps];   // package_outline 被静默丢弃
```

图集中出现了 `package_outline`（p.32 封装图），说明本次走的是 `need.figures === true` 的 Gemini 分支。

### 2.3 结论

**把几何交给了 AI。** `lib/gemini.js` 要求模型输出归一化 bbox 并声明 `origin TOP-LEFT`，但 VLM 读 PDF 时并没有真实的视觉栅格坐标——bbox 是猜的，原点方向也不受提示词约束。这直接违反本项目的核心原则：*AI 负责语义，确定性引擎负责几何*。

v0.8.8 的 `＋留白` 与空白探测是在错误坐标上做补偿，因此无论怎样调整都不可能收敛。

### 2.4 三个次生缺陷

1. `cropInner()` 未钳制源矩形，`sy + sh` 超出画布时越界部分被绘为**透明**，导出 PNG 出现整片空白。
2. 空白探测把 PNG 画到全新的透明 canvas 上采样，透明像素 `rgba(0,0,0,0)` 被判为 `nonWhite` ⇒ 阈值 `nonWhite < 6` 几乎永不成立，告警形同虚设。
3. `findFigures()` 丢弃 `package_outline` ⇒ 只要需要封装图，整个图区路径就被迫回退到不可信的 Gemini bbox。

## 3. 修复

### 3.1 新增 `src/figfit.js` — 图区几何确定性引擎

纯函数、不依赖 DOM/pdfjs、可单测。定位链路按可靠性降序：

| 路径 | 方法 | 说明 |
|---|---|---|
| A | `caption_up` / `caption_down` | **标题锚定**。用 PDF 文本层定位图注真实坐标，再按墨迹分布向上/下生长出图块。方向由 `图N-M.` / `Figure N.`（图在上）与 `7.2 xxx` 章节号（图在下）判定，无法判定时比较两侧墨量。 |
| B | `seed_trim` / `seed_mirror` | 无图注时以 AI 框为**种子**：先内缩去空白，再向外吃回被截断的引脚标注；若种子区域近乎空白而其纵向镜像有内容，则自动镜像纠偏。 |
| C | `largest_block` | 兜底：页面按空白带切块，取墨量最大者（与种子纵向重叠者优先）。 |
| — | `null` | 整页无可用图块时返回 `null`，宁可报错也不给假图。 |

关键实现要点：

- **透明像素按纸白处理**（`a < 16 → lum = 255`），否则 pdf.js 未绘制区域会被整片当成黑墨。
- **正文行是硬边界**：文本层中长度 > 40 字符的行标记为 `stopRows`，生长不得跨越——示意图内几乎不会出现连续长行。
- **页眉页脚剔除**：`detectChrome()` 识别 `提交文档反馈 / English Data Sheet / Copyright © / www.*.com / 纯页码` 等每页装饰行，把内容下界缩回其上方，从根本上杜绝"裁到页脚"。

### 3.2 `src/pdf.js`

- `renderPage()` 增加按 `doc → 页码|宽度` 的缓存，并显式铺白底。
- 新增 `getTextLines(doc, pageNum, viewport)`：经 `Util.transform(viewport.transform, item.transform)` 得到**设备像素、原点左上**的文本行坐标，与 canvas 同基准。
- 新增 `analyzePage()`：渲染 + 墨迹图 + 文本行 + chrome 边界，一页只算一次。
- `cropInner()` 源矩形一律钳制在画布内，输出 canvas 先铺白底。

### 3.3 UI 与数据流

- `FigureGallery` 在渲染前调用 `autoFitFigure()`，并把结果 **写回 `figures`**（`bbox` / `fitMethod` / `fitCaption` / `aiBbox`），保证「图集所见 === 导出与 ezPLM 所得」。写回后 effect 二次运行时因 `fitMethod` 已置而跳过重算，不会成环。
- 每张卡片显示几何来源徽章（`标题锚定` / `镜像纠偏` / `最大图块` / `⚠ AI 原框`），贴合失败时明确标注坐标不可信——遵循证据绑定与诚实 UX 原则。
- 新增「重新贴合」按钮（图集与 ④ 编辑器各一处）；手动框选标记为 `manual`，不会被自动贴合覆盖。
- 空白探测改为直接查墨迹图，准确且无需解码 PNG。
- `App.jsx` 在 `reviewedIr` 回写时按 `figureId` 保留 `fitMethod/fitCaption/aiBbox`，避免手动框选在生成后被自动贴合覆盖。

### 3.4 服务端

- `lib/heuristics.js`：`findFigures()` 返回值补回 `package_outline`（上限 2），减少对 Gemini 图区路径的依赖。
- `lib/gemini.js`：提示词重心转移——`page` 必须精确、`title` 必须**逐字照抄印刷图注**（客户端据此在文本层锚定），并明确告知 `bbox` 仅为兜底粗略提示，无需在其精度上纠结。

- 真实 Gemini 调用、KiCad CLI/DRC/STEP、云端 PostgreSQL、S3 对象存储仍未在生产环境验证。
- `＋留白` 目前是纯客户端状态，不写回 IR；跨会话不保留。
