# v0.8.10 — 「重新框选」跳转失效修复

## 1. 现象

在截取图集点「重新框选」后，④ 图区截取跳到某一张**固定的**图（对应固定的 PDF 页），
必须再点一次该图的类型页签，才能回到目标图去「确认此图」。

## 2. 根因

两个缺陷叠加，都在 `FigureEditor` 的选中态模型上。

### 2.1 跳转信号是"常驻值"而不是"一次性事件"

```js
// App.jsx（旧）
const [recropFigureId, setRecropFigureId] = useState(null);
onRecrop={(figureId) => { setConfirmTab('figs'); setRecropFigureId(figureId); }}

// FigureEditor.jsx（旧）
useEffect(() => {
  if (!focusFigureId) return;
  const i = figures.findIndex((f) => f.figureId === focusFigureId);
  if (i >= 0) setActive(i);
}, [focusFigureId, figures]);
```

`recropFigureId` 一经设置就再不清空，于是：

- **重复点击同一张图无效**：第二次点击时 `focusFigureId` 的值没变 → props 无变化 → effect 不触发 → 编辑器停在用户上次停留的那张图。而此时 ④ 已经挂载，`scrollIntoView` 生效，把用户滚到编辑器面前 —— 看到的正是那张"固定的"图。
- **反向拽回**：effect 依赖 `figures`，而 v0.8.9 起 `figures` 会因自动贴合写回、确认、改标题等频繁换新身份，每次都把用户强行拉回上一次的跳转目标。

### 2.2 当前图用数组下标记录

```js
const [active, setActive] = useState(0);
const fig = figures[active];
```

下标在图集「丢弃」或服务端 `reviewedIr` 回写导致数组重排后会指向另一张图。
且编辑器挂载时 `active = 0`，在跳转 effect 生效前先渲染 `figures[0]` 的页面。

### 2.3 顺带发现：滚动在挂载前执行

```js
setConfirmTab('figs');
document.querySelector('.figure-editor')?.scrollIntoView(...);   // 此刻组件还没挂载 → null
```

`confirmTab` 默认 `'pins'`，首次点击时 ④ 尚未挂载，`querySelector` 必然落空，页面不滚动。

### 2.4 顺带发现：页面新增的图区缺 `figureId`

`＋` 与「＋ 添加图区」创建的图没有 ID，导致：

- 无法被「重新框选」定位（`onRecrop(undefined)`）；
- 会被 `App.jsx` 补丁构造逻辑 `if (!f.figureId) continue;` **静默丢弃**，永远存不进 IR；
- 在图集里 `f.figureId === undefined` 会一次命中所有缺 ID 的图，改一张等于改多张。

## 3. 修复

### 3.1 新增 `src/figstate.js`

把选中态的纯逻辑从 JSX 里抽出来，可单测：

| 函数 | 职责 |
|---|---|
| `newFigureTempId()` | 页面新增图区的稳定临时 ID（`fig_tmp_*`） |
| `withFigureIds(list)` | 入口处补齐缺失 ID |
| `resolveActiveIndex(figures, activeId)` | 按 `figureId` 解析当前图，找不到回落首张 |
| `shouldConsumeFocus(req, handledSeq, figures)` | 一次性令牌消费判定 |
| `nextActiveAfterRemoval(figures, i)` | 删除后的落点 |

### 3.2 跳转改为一次性请求令牌

```js
// App.jsx
const [recropReq, setRecropReq] = useState(null);      // {figureId, seq}
const recropSeqRef = useRef(0);
const handleRecropHandled = useCallback(() => setRecropReq(null), []);
onRecrop={(figureId) => {
  if (!figureId) return;
  setConfirmTab('figs');
  setRecropReq({ figureId, seq: ++recropSeqRef.current });
}}
```

`seq` 递增保证"对同一张图连续点击"仍然触发；`handledSeqRef` 保证同一请求只消费一次，
`figures` 再怎么变都不会把用户拽回去。`onFocusHandled` 用 `useCallback` 稳定引用，
避免作为 effect 依赖时每次渲染都重建。

### 3.3 当前图改用 `figureId` 主键

`active`（下标）→ `activeId`（ID）。`previews` 由 `index → dataURL` 改为 `figureId → dataURL`；
`aiBboxRef` 由数组改为 `Map`；`updFig` 由按下标写改为按 ID 写；类型页签 `key` 用 `figureId`。

### 3.4 滚动交给编辑器自己

`FigureEditor` 根节点挂 `rootRef`，在消费跳转请求时 `requestAnimationFrame` 后
`scrollIntoView({block:'start'})` —— 挂载完成后才滚，不再依赖调用方猜时机。

### 3.5 ID 兜底

`App` 在 `setFigures(withFigureIds(data.figures))` 处统一补齐；
`FigureEditor` 的两个新增按钮显式带 `newFigureTempId()`；
`FigureGallery` 的 `upd/remove/bump` 加 `figureId &&` 守卫，杜绝 `undefined` 一次命中多张。

新增 `test/v0810.test.js` 共 10 例，其中三例直接对应本次现场缺陷：

- 「对同一张图连续点『重新框选』仍会触发」（旧实现在此失效）
- 「同一请求只消费一次，figures 变更不得反复拽回」
- 「按 figureId 定位，数组重排后仍指向同一张图」

## 5. 遗留

- ④ 编辑器与图集的滚动锚点仍是整块 `.figure-editor`；若图区较多，跳转后可能仍需微调视口。
- `＋留白` 仍为纯客户端状态，不写回 IR。
- 扫描版 PDF 的标题锚定依赖 OCR 文本行接入 `analyzePage`，尚未完成。
