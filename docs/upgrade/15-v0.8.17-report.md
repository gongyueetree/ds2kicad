# v0.8.17 — QFN 3D 端子被本体吞没

## 1. 现象

TMUXL27518（WQFN-24, 4×4mm）的在线 3D 预览里，四条边的引脚看起来"连成一片"，
分不出单个端子。

## 2. 根因：竖直方向互穿，不是横向间距不够

先排除横向：端子宽 `lw = min(0.35, pitch × 0.5) = 0.25mm`，间距 `pitch = 0.5mm`，
缝隙 0.25mm，每边 6 个 —— **横向几何完全正确**。

问题在 Y 轴：

```
本体：y 0.02 → 0.66 mm     X 半宽 1.960 mm   (bodyLength × 0.98 / 2)
端子：y 0.00 → 0.20 mm     X 1.60 → 2.00 mm
```

- 端子占 `0 ~ 0.2mm`，本体从 `standoff = 0.02mm` 起 → **端子 90% 埋在环氧本体内部**；
- 横向也只有 `2.00 - 1.96 = 0.04mm` 探出本体外。

于是每个端子只剩一道 0.04mm 宽的边缘可见，24 道碎片沿一条边挤在一起，
再叠加本体与端子表面互穿导致的 z-fighting，视觉上就成了一条连续的银色条带。
EP 同理：`box(0, 0.05, 0, 2.45, 0.1, 2.45)` 整块在本体内部，**完全不可见**。

QFN 是无引线封装，端子是本体**底面**的裸露金属块，本体应当叠在端子层之上；
原实现把两者放在同一高度区间，属于建模拓扑错误。

## 3. 修复

```js
const termH = pkg.family === 'qfn' ? Math.min(0.25, Math.max(0.08, pkg.height * 0.25)) : 0;
const bodyH = pkg.family === 'qfn' ? Math.max(0.2, pkg.height - termH) : ...;
const standoff = pkg.family === 'qfn' ? termH : ...;
```

- 端子层 `0 ~ termH`，本体 `termH ~ height`，两者不再重叠；
- `端子层 + 本体 = 手册标称总高`（4×4×0.8 的 WQFN 实测总高仍为 0.800mm，未溢出）；
- EP 移到与端子同层，从本体下方可见；
- 端子外沿仍与本体标称边齐平（`e = bx/2 - ll/2`），本体按 0.98 内缩，
  端子沿各边微露，符合 QFN 实物观感。

只影响 `qfn` 家族。`dual` 的鸥翼脚尖在 `leadSpan/2 > bodyWidth/2` 处、
`dip` 的引脚在 `rowSpan/2 > bodyWidth/2` 处，本就在本体之外，未做改动
（并有专门用例防止误伤）。

## 4. 为什么 QA 报告没发现

报告第 5.5 节写道：12/12 个 WRL "具备正确头、引脚/焊盘拓扑及 Pin 1 标记，
模型平面外形与提取尺寸的差异均不超过 2.1%"。

审核脚本验的是**节点数量、拓扑分类和平面尺寸** —— 这三项本来就是对的
（端子确实生成了 24 个、位置也对）。缺的是**遮挡/互穿检查**：几何存在
不等于可见。新增用例正是补这一维度。

## 5. 验证

```
node --test test/*.test.js
# tests 223 / pass 211 / fail 0 / skipped 12

VITE_EZPLM_ORIGINS=... npm run build   # ✓
```

`test/v0815.test.js` 新增 5 例（DSK-014），并做了反向验证 —— 回退修复后
其中 3 例失败：

- 端子不得与本体竖直互穿（**回退后失败**）
- 相邻端子之间必须有正缝隙
- EP 必须与端子同层可见（**回退后失败**）
- 总高仍等于手册标称，底面落在 y=0（**回退后失败**）
- 不得误伤 dual / dip

## 6. 遗留

- WRL 仍是参数化近似模型，`approximate_parametric_3d_not_vendor_step` 阻断不变，
  不可作为机械干涉依据。
- 端子层厚取 `height × 25%`（上限 0.25mm）是观感取值，非手册实测；
  手册若给出端子厚度（terminal thickness）应优先采用，目前提取管线未采集该字段。
