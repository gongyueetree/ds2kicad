# v0.8.18 — 几何守卫容差过松导致符号/封装/3D 比例失真

## 1. 现象

LMV331X 的 SOT23-5：符号本体是个近正方形大框、封装 F.Fab 轮廓明显过长、
3D 呈细长条状。文件名 `LMV331X_SOT23-5_1.6x4.9mm_P0.95mm` 直接暴露了原因 ——
**SOT23-5 本体标称 2.9×1.6mm，这里是 4.9mm**（4.9 是 SOIC-8 的长度）。

三种产物都"按同一个错误值忠实地生成"，所以看起来是"比例问题"，实际是**输入尺寸错误
穿透了两道几何守卫**。

## 2. 根因：两道防线各差一点点

### 防线一：JEDEC 先验替换（容差 ±70%）

```js
if (!v || v < prior[k] * 0.55 || v > prior[k] * 1.7) { /* 替换 */ }
```

SOT23-5 的 `bodyLength` 先验 2.9mm，AI 给 4.9mm，误差 **+69%**，
而触发阈值是 `2.9 × 1.7 = 4.93mm` —— **差 0.03mm 没触发**。

JEDEC 公称尺寸的真实公差在 ±5% 量级，±70% 的容差窗口宽到失去意义。

### 防线二：本体长与引脚数关系校验

```js
const maxLen = rowLen + Math.max(4, p.pitch * 3);
```

5 脚每边 3 脚 × 0.95mm → `rowLen = 1.90mm`，上限 `1.90 + max(4, 2.85) = 5.90mm`。
4.9mm 同样放行。

问题在那个 **4mm 是绝对裕量**：对 SOT23-5 这类小封装，等于允许本体比引脚行长 4mm
（+210%），形同虚设。它是为 DIP 这类大封装设的，却无差别应用到了所有 dual 家族。

## 3. 修复

### 3.1 先验容差按字段收紧

```js
const TOLERANCE = { pitch: 0.15, bodyLength: 0.30, bodyWidth: 0.30, leadSpan: 0.30, height: 0.55 };
const tol = TOLERANCE[k] ?? 0.30;
if (!v || v < prior[k] * (1 - tol) || v > prior[k] * (1 + tol)) { /* 替换 */ }
```

`height` 单独放宽到 ±55%：同封装常有薄型变体（SOT-23 1.45mm vs TSOT-23 0.9mm），
不应因此触发替换。`pitch` 收到 ±15%：间距是离散标准值，偏差必属错误。

### 3.2 长度上限改为随 pitch 缩放

```js
const maxLen = rowLen + Math.max(p.pitch * 3, Math.min(4, p.pitch * 3 + 1.2));
```

细间距封装的端部裕量本就随 pitch 收窄。各 pitch 下的裕量：

| pitch | 0.4 | 0.5 | 0.65 | 0.95 | 1.27 | 2.54 |
|---|---|---|---|---|---|---|
| 裕量(mm) | 2.40 | 2.70 | 3.15 | 4.00 | 4.00 | 7.62 |

大封装（DIP 2.54mm）的裕量不减反增，不影响既有行为。

## 4. 修复效果

同一份错误输入（bodyLength=4.9）：

| 产物 | 修复前 | 修复后 |
|---|---|---|
| 文件名 | `1.6x4.9mm` | `1.6x2.9mm` |
| 焊盘沿引脚跨度 | 1.90mm（本就正确） | 1.90mm |
| 3D 本体 | 1.57 × 0.88 × 4.84mm | 1.57 × 0.88 × **2.84**mm |
| 3D 长宽比 | 3.06 | **1.81**（标称 2.9/1.6 = 1.81） |

并留下结构化记录 `jedec_prior_substitution`（from 4.9 → to 2.9）与中文告警，
按既有规则**阻断晋升**，要求人工对照机械图复核。

## 5. 验证

```
node --test test/*.test.js
# tests 227 / pass 215 / fail 0 / skipped 12

VITE_EZPLM_ORIGINS=... npm run build   # ✓
```

新增 4 例并做反向验证（回退容差与上限公式后，其中 3 例失败）：

- SOT23-5 的 4.9mm 必须被先验拦下并留痕；
- 端到端：文件名 / 焊盘跨度 / 3D 长宽比三者与标称一致；
- 长度上限不再使用绝对裕量（用 TSSOP-6 构造，该类型有 pitch 先验但**无 bodyLength 先验**）；
- **不得误伤**：SOT23-5 标称值、TSOT-23-5 薄型变体、SC70-5、SOIC-8 的 4.9mm、
  TSSOP-14 的 5.0mm 均须原样保留。

## 6. 遗留

- 先验表仅覆盖 7 类小信号封装。未收录的类型（QFN/DFN/LGA 等）仍只有关系校验兜底。
- `bodyLength` 按设计不设先验（与引脚数相关），因此**引脚数或 pitch 本身读错时，
  关系校验会以错误基准推导** —— 这是当前守卫的能力边界。
- 本次未改动提取侧。AI 把 2.9 读成 4.9 的原因未追查，可能与机械图中多个尺寸标注
  被混淆有关；根治需在 `gemini.js` 侧要求逐尺寸绑定证据锚点。
