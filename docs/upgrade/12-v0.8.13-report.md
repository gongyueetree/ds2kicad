# v0.8.13 — 复核面板空白 / 按钮不可见

## 1. 现象

配好 JWT、`sessionAuthenticated` 为 true 之后，⑥ 复核与发布里看不到「标记已复核」按钮。

## 2. 代码里两处会静默渲染成空白

### 2.1 `if (!rows.length) return null;`

`rows` 来自 `bundle.assetKeyPromotion`。只要该字段缺失或为空，整个面板返回 `null`，
页面上就只剩一个 `<h2>⑥ 复核与发布</h2>` 的空卡片 —— 表现完全就是"没有按钮"。

最常见的触发条件：**后端仍是旧版本**（`assetKeyPromotion` 是 v0.8.12 才加进响应的），
或者**还没重新点过「生成」**（面板读的是生成结果，不是提取结果）。

而且这个判断本身就是错的：`review` 动作**不需要 assets**，即使一个资产键都没拿到，
「标记已复核」也应该可用。

### 2.2 `sessionAuthenticated === true` 与「有 reviewer 角色」是两回事

```js
const canReview = hasRole(session, 'reviewer');   // api/generate.js
hasRole = (s, r) => Array.isArray(s?.roles) && s.roles.includes(r);
roles = normalizeRoles(p.roles ?? p.role ?? p.scope);   // lib/auth.js
```

JWT 验签通过 → `authenticated: true`；但若载荷里**没有 `roles` 声明**（或不含 `reviewer`），
`canReview` 就是 `false`，按钮被 `disabled`。原来只在提示行里挂了一个很小的
`无 reviewer 角色` 徽章，太容易被忽略；而且即使强行点了，`authorizeJobAccess` 也会以
403 `insufficient_role` 拒绝。

这是本次最可能的真实原因：`sessionAuthenticated` 已经是 true，说明验签没问题，
但 ezPLM 签发的 JWT 里缺角色声明。

## 3. 修复

1. **删掉 `return null`**。面板在任何情况下都渲染，动作条无条件显示。
2. **新增「会话与权限诊断」区**（无资产键或缺 reviewer 角色时默认展开），逐项列出
   `sessionAuthenticated` / `canReview` / `canPublishRole` / `state` / `revision` / 资产键数量，
   并对每个异常值直接给出该改哪里。服务端未返回该字段时显示"未知（多半是后端仍是旧版本）"。
3. **缺角色时就地给出红字说明**：需要在 JWT 中加入 `"roles": ["reviewer"]`（发布还需
   `publisher`），并点明"`sessionAuthenticated` 为 true 只说明验签通过，与角色是两回事"。
4. **补齐授权类错误码的文案**：`insufficient_role` / `tenant_mismatch` / `not_job_owner`
   不再只显示服务端原文。

## 4. 需要在 ezPLM 侧确认的 JWT 载荷

```json
{
  "sub": "<用户 ID>",
  "name": "<显示名>",
  "tenantId": "<租户 ID，必须与作业一致>",
  "roles": ["reviewer", "publisher"],
  "iss": "<与 EZPLM_JWT_ISS 一致>",
  "aud": "<与 EZPLM_JWT_AUD 一致>",
  "exp": 1234567890
}
```

`roles` 也接受 `role` 或 `scope`（`normalizeRoles` 会统一处理）。`tenantId` 不匹配会得到
403 `tenant_mismatch`。

- `revoke` 未接入面板；model3d 的结构性阻断仍需厂商 STEP 链路。
