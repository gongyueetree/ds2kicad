# v1.2 Multi-Channel Agent Platform — implementation report

This change turns the existing DS2KiCad core into a deployable public Agent entrypoint for EETree, Tindie, ezPLM and eeHub without rewriting the proven extraction/generation pipeline.

## Implemented

- Signed Guest Session: HttpOnly cookie + `X-Guest-Session` header fallback for third-party iframe/browser cookie restrictions.
- Server-side Trial/Credit Wallet with PostgreSQL persistence and development in-memory fallback.
- Reserve → Commit / Refund billing semantics: failed extraction does not consume quota.
- Multi-channel attribution (`eetree`, `tindie`, `ezplm`, `eehub`, `direct`) and locale-aware signup target.
- Guest → ezPLM/eeHub Handoff token API carrying guest ID, source, return URL and optional job ID.
- Top platform shell showing trial/member state, remaining Credits and account CTA.
- Unified PDF / PNG / JPG upload. Images are deterministically wrapped into a one-page PDF in browser, then pass through the existing evidence/extraction pipeline.
- Existing editing, generate, reload, figure and lifecycle API calls inherit the same Guest Token.
- Vercel public wrapper endpoint `/api/platform-extract` keeps `/api/extract` available for trusted/internal integration.
- Admin-only `/api/credits` top-up endpoint for testing until the real Billing Service is connected.

## Public endpoints

- `POST /api/platform-session` — create/read Guest or authenticated platform session and return wallet state.
- `POST /api/platform-extract` — quota-gated Datasheet→KiCad extraction.
- `GET /api/credits` — wallet state.
- `POST /api/credits` — trusted test top-up (requires `CREDIT_ADMIN_SECRET`).
- `POST /api/handoff` — create ezPLM/eeHub registration handoff URL.

For UI-only smoke tests set `MOCK_MODE=1`; Mock extraction is deliberately free.

## Security / product boundaries

- Guest tokens contain no secret and cannot approve/publish verified assets. They only identify a quota-limited anonymous draft owner.
- Verified review/publish still requires authenticated ezPLM/eeHub roles.
- The Handoff API creates a signed transfer token; ezPLM/eeHub must implement the receiving/claim callback before anonymous draft assets can be permanently moved into a user workspace.
- Current working core is Datasheet/Image → KiCad Symbol/Footprint/3D. `schematic_to_kicad` Credit pricing is reserved, but raster/PDF schematic reconstruction is a separate next-stage runtime and is not falsely exposed as complete in this commit.

## Verification

New platform unit tests cover signed Guest identity, iframe header fallback, Handoff attribution, Reserve/Refund/Commit and quota exhaustion. Existing repository tests should remain unchanged and Vercel build should run with the normal `npm run build` command.
