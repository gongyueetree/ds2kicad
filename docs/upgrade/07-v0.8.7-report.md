## 本轮由测试抓出的真 bug（5 个）

1. **状态机不允许 approved 下继续 approve** → 分批批准根本走不通。
2. **review 动作不生成 Manifest** → Manifest 停留在跃迁前状态。
3. **draft fork 发生在生成之后** → 产物 state 与最终 state 不一致（被 verifyConsistency 拦下）。
4. **landPattern 裸值 / addPins / removePins 绕过 reason 校验** → item 6 形同虚设。
5. **管脚 number/type 修改不生成 EvidenceAnchor**（只有 name 有）。

另修正 `reason` 长度门槛过严（`>=2` 会挡掉 "p63" 之类合法短理由），改为非空即可。

## 追加修复：线上「截取图集」空白（用户实测反馈）

根因是**上传通道**：`/api/extract` 只在 live/degraded 分支缓存 PDF 字节，
mock/上传路径没有缓存 → `pdfUrl` 为 `local:xxx.pdf` 且库中无字节 → `/api/job-pdf` 返回 409 → 图集全片空白且无提示。

修复三处：
1. mock/上传分支同样缓存 PDF 字节（≤6MB，用已解码的 `uploadedBuf`）；
2. 前端 `loadPdf` **优先使用浏览器已持有的上传字节**，不再绕服务端；
3. 图集把 HTTP 失败原因落到每张卡片（409/401/403 分别给出可操作说明），杜绝"空白但无提示"。

同时修复慢速源站 502：`analog.com` 等延长单次超时并自动重试一次，失败信息附「改用上传通道」建议。

**过程中发现并修复一个会导致请求永久挂起的真 bug**：mock 分支引用了尚未 `let` 声明的 `pdfBuf`（TDZ），
Express 未捕获 → 请求悬挂（与 v0.8.6 的 `num is not defined` 同类）。已改用 `uploadedBuf`，
并给 `/api/extract` 加了 handler 级异常兜底，任何未预期异常都返回 500 而非悬挂。
